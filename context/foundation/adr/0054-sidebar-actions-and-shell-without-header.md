# The shell has no header bar, the sidebar does not collapse and carries the actions

The shell of the app loses the top bar with the page title and breadcrumbs, the sidebar stops collapsing on desktop, and it takes over what the `Sidebar` and `CommandPalette` components of the "C · Atrament i morski" design system show (artifact https://claude.ai/artifact/9gJSdtfpFgUAa8oEMgR4HA): the budget year in segments, global shortcuts with hints and a "Szukaj i przejdź ⌘K" palette. This ADR records those decisions in one place and says which paragraphs of ADR-0053 and ADR-0052 stop applying. It is implemented in four phases of the change `sidebar-action`; the paragraphs for later phases are the decisions those phases follow.

Shell without a header. `AppSidebarHeader`, `Breadcrumbs`, `components/ui/breadcrumb/*`, the type `BreadcrumbItem` and the layout prop `breadcrumbs` are removed, together with every `setLayoutProps({ breadcrumbs })` call. Each page already has its own `h1.page-title`, so the title only disappears from the bar; `main` starts with the title row of the page. This replaces ADR-0052, paragraph 1, where the last breadcrumb item "Podgląd importu" was part of the step 2 title row.

No collapse on desktop. `AppShell` passes `SidebarProvider` a controlled `:open="true"` and `AppSidebar` uses `collapsible="offcanvas"`. The icon mode and the 3rem strip of ADR-0053 (paragraphs "Width" and "Section labels", the sentence about the tooltip of the year) no longer exist: `group-data-[collapsible=icon]` and `:tooltip` leave `NavMain`, `NavUser`, `AppLogo` and `UserInfo`. The shared prop `sidebarOpen` and the cookie `sidebar_state` are no longer read or exempted from encryption; a stale cookie in a browser does nothing. `collapsible="none"` is not an option, because `ui/sidebar/Sidebar.vue` then renders a fixed column on a phone as well, without the `Sheet`. The primitives in `ui/sidebar/*` do not change: a controlled `open` makes `setOpen` from Ctrl/⌘+B a no-op on desktop, while on a phone the shortcut still opens the sheet.

Phone bar. On a phone (width up to 768 px, the breakpoint of `SidebarProvider`: `useMediaQuery("(max-width: 768px)")`) the only entry to the sheet was the trigger in the removed bar. `AppMobileBar` (the `SidebarTrigger` named "Otwórz menu" and the mark "HT" with the name of the product, a link to Dashboard, without a page title) is rendered by `AppContent` when `isMobile` from `useSidebar()` is true. It does not hide with Tailwind `md:hidden`, because `md` starts at 768 px and at exactly 768 px the sidebar is already a sheet while the bar would be hidden. The component itself always draws the bar, so the kitchen sink can show it.

Year in segments. "Rok budżetu" becomes segments: every year with a budget in ascending order plus one "<highest + 1> +", three per row; with no budget a single "<current year> +". Choosing a year is one click with the pending state and the error toast kept; "+" opens the new-budget dialog with that year, from one shared instance in the shell. This reverses the rejection of segments in ADR-0053 (they did not fit the 3rem strip, which no longer exists) and replaces its year button; the unlimited growth of the list is accepted and the rows wrap. The logic lives in `lib/budget-year-segments.ts`.

Shortcuts. Menu items carry a shortcut marker `1`–`n`, the number coming from the position on the shared list of views (`useAppViews`), never from a literal, so a view added later (for example "Raporty") gets the next number and the text "1–n" follows. Above the user block a line "Skróty: 1–n widoki, N nowa operacja, / szukaj, Esc zamknij." is shown. `1`–`n` open a view, `N` opens the "Dodaj operację" menu on Operations, `/` focuses the Operations search; from another page the intent is kept on the client in one shared ref and the visit goes to Operations first, with no new URL parameter. Shortcuts are silent with Ctrl/⌘/Alt, during composition and on key repeat, in text fields, `textarea`, `select` and `contenteditable`, and while a reka layer (dialog, sheet, menu, listbox) is open; every handled shortcut calls `preventDefault`. `/` is Shift+7 on a Polish keyboard, so the predicate does not reject Shift for it. The marker inside the link is `aria-hidden` and the shortcut goes to `aria-keyshortcuts`, so the accessible name of the link stays "Dashboard". This reverses the rejection of shortcuts in ADR-0053.

Palette. "Szukaj i przejdź ⌘K" in the sidebar and ⌘K/Ctrl+K open a palette built on the shadcn-vue `command` component (reka `Listbox*` with `useFilter`), without overwriting the local `ui/dialog`, which is adapted to Atrament; the palette uses reka `Dialog` with the local `DialogContent`. The registry's `ListboxFilter` gives no `role="combobox"`, `aria-expanded` or `aria-controls`, so the input is given them in the palette; if `CommandInput` does not forward attributes to `ListboxFilter`, the fix is made in `ui/command` for every consumer and named in the phase that makes it. The groups are "Widoki i akcje" (views with their shortcuts, "Dodaj operację", "Importuj CSV", "Dodaj rok budżetu", "Ustawienia") and "Kategorie: operacje" (active expense and income categories of the year chosen in the sidebar, each with its annual execution, linking to Operations filtered by that category and year). Archived categories, categories of other years, monthly execution, logout, theme switching and separate "add expense/income/…" items are out of scope. The categories come from a JSON endpoint called on every open of the palette (`useHttp`, one query on `categories.execution_minor_units` of one budget), not from a shared prop or a partial `router.reload({ only })`: a partial reload runs the whole action of the current page's controller (only closures are lazy), so on Operations it would recompute the list. The width is the dimension token `--command-palette-width` (520 px, no `.dark` variant). This reverses the rejection of the palette in ADR-0053.

Rows in `ui/command`. If accessibility forces a change in the row components of `ui/command` (for example forwarding `id` and `aria-*` to the listbox or the filter), it is made there for all consumers, not for one screen. In phase 4 the registry `CommandInput` already forwards `$attrs` to `ListboxFilter`, so `role="combobox"`, `aria-expanded`, `aria-controls` and `aria-autocomplete` need no change there. The deviations from the registry are in `Command.vue`: it exposes `highlightFirstItem` of its `ListboxRoot`, so every consumer can highlight the first item on open (the palette needs it for "first item selected, Enter runs it"), and it filters again when the number of registered items changes, because items that mount after the user has typed (the palette loads its categories from the server) would otherwise stay unfiltered and their group hidden until the next keystroke. The registry filter matches the rendered text with the browser locale, where `pl` treats `ż` and `ł` as separate letters, so each palette item also renders a hidden copy of its label without diacritics; "zywnosc" finds "Żywność" whatever the locale. The files were written from the registry JSON by hand (the CLI would also pull its own `dialog`).

It changes no rule in `context/foundation/glossary.md` and no _Avoid_ term. It removes one shared Inertia prop (`sidebarOpen`), on both sides in the same commit with an `assertInertia` check, and adds no package.
