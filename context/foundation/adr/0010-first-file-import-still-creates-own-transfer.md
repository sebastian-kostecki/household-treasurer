# First-file Import still creates a full Own Transfer

Stage 2 pairing can convert a first-leg Financial Operation, so a correct ledger does not require the first file to be classified as Own Transfer. We still keep today’s first-file classification: the User may mark a row as Own Transfer, pick the other Account, and both balances move on that commit. We do not wait for a second Import before the Own Transfer exists, and we do not restrict first-file Own Transfer to cash. Cash has no bank file, so ATM (bank to cash) would otherwise have no Import path; a User who already knows the other Account should move Liquidity now. File-one preview chrome stays as today: default type from the signed amount, no Opis preselect or badge — mBank “wewnętrzny” is not this User, and pairing already ignores those phrases. We rejected waiting for both files (ATM and delayed Liquidity) and a cash-only first-file type (the same Own Transfer already covers ATM and bank-to-bank).
