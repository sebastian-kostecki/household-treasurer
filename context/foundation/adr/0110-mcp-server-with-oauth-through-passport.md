# An MCP server for the budget: local stdio, a public `/mcp` behind Passport OAuth, read tools on the `app/Support` readers and one cash write tool

The app has no machine interface (`tech-stack.md` §2: „Osobne REST/JSON API nie powstaje w MVP”, §7: „API | brak”). The user wants to ask Claude about the budget (To Spend, plan against execution, balances, recent operations) from Claude Code on the laptop and from claude.ai, Claude Desktop and the phone, and to record a cash expense from the phone. A phone cannot reach a stdio process, so the same tools must also be served over HTTP, to one user's production data, behind OAuth. This ADR supersedes the sentence and the table row above and amends ADR-0079 for the MCP answers only.

Server. `laravel/mcp` (`^1.2`, a production dependency from now on; it was a transitive dev dependency of Boost). `routes/ai.php` registers `Mcp::local('treasurer', LocalTreasurerServer::class)` for Claude Code through Sail (`php artisan mcp:start treasurer`) and `Mcp::web('/mcp', TreasurerServer::class)` for production. `TreasurerServer` lists the tools; `LocalTreasurerServer` extends it and only adds the local user (`MCP_LOCAL_USER`, set with `Auth::guard('web')->setUser`, only in the `local` environment). Only `TreasurerServer` is served over HTTP, so a request can never reach the local login. Tools are thin: every query starts at a `$user->…` relation, amounts come from the `app/Support` readers and are never recomputed in a tool, "today" is `AppDay::today()` (ADR-0103) and every answer carries `app_day`. The orchestration that a page and a tool both need moves out of controllers into `app/Support` (`BudgetForYear`, `CurrentMonthReading`, `MonthTiming`, `FinancialOperationRows`) with no change of any Inertia prop. No MCP resources or prompts, no streaming.

Authorisation. `/mcp` is protected by Laravel Passport 13 as the OAuth authorization server (authorization code with PKCE, Dynamic Client Registration through `Mcp::oauthRoutes()`), one scope `mcp:use`, access tokens for 1 hour and refresh tokens for 30 days, keys in `PASSPORT_PRIVATE_KEY`/`PASSPORT_PUBLIC_KEY` (env, not files: a file generated by `deploy.sh` would belong to root and be unreadable by FPM, and `storage/` is outside the backup set). Redirect targets are restricted in `config/mcp.php` to `https://claude.ai`, `https://claude.com` and loopback. Sign-in reuses the existing login (password, 2FA, passkey); the consent page is a Polish Atrament Inertia page in `AuthLayout` that posts a native form to Passport's approve and deny routes, because they answer with a 302 to an external `redirect_uri`. A login that ends at `/oauth/authorize` leaves the Inertia XHR chain with a full-page navigation. Remote calls are logged to a dedicated `mcp` channel (user id, JSON-RPC method, tool name, status, duration; never arguments, amounts or descriptions), limited to 60 a minute per user, and unused registered clients are pruned daily.

Month Category Group sums on the server. ADR-0079 keeps group sums on the client so they follow the typed plan in edit mode. MCP has no edit mode, so `App\Support\MonthPlanGroupSums` mirrors the read mode of ADR-0079 for MCP answers only, and a parity test proves it equals `monthPlanGroupTree` on shared fixtures. The page still never takes group sums from the server.

Write. One tool records a cash expense, refund or income. It is idempotent by a `request_id` kept in its own table `mcp_operation_requests` (unique `(user_id, request_id)`, cascading from the user and from the operation), always asks the user for approval (`anthropic/requiresUserInteraction`) and is registered only when `MCP_WRITE_ENABLED` is true (default false, read by `config:cache`, so a change needs `scripts/artisan.sh config:cache`). Its answer states the App Day, the account balance and To Spend before and after, and warns when To Spend goes below zero and lower. It reuses the hand-entry rules, made callable without HTTP.

We rejected:

- a Sanctum token (the static headers for connectors are a beta for limited organisations, and a token pasted into a phone is a standing credential);
- custom read and write scopes (one user, one scope; the write switch and the forced approval carry the risk);
- a Blade consent view (the app's UI is Inertia and Atrament; a Blade page would be a second look and a second place for tokens);
- a key column on `financial_operations` (it would change the user snapshot, version 13 to 14, for a value that only matters for a retry window);
- a port of the TypeScript entry warning to the write answer (the answer warns about the operation's month only; later months of an Irregular period are not warned about);
- a fallback to an earlier year when the App Day year has no Budget in execution (ADR-0075 stays out of tools; the answer names the year and its phase);
- group sums read from the server by the page (ADR-0079 stands for the page).
