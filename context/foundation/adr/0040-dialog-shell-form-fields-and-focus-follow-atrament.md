# Dialog shell, form fields and focus follow Atrament

The dialog, the form field and the focus ring follow the "C · Atrament i morski" system README (artifact https://claude.ai/artifact/9gJSdtfpFgUAa8oEMgR4HA, components Dialog, Field and Button), applied to every dialog in the app through the `ui/*` primitives.

The dialog shell is 460px wide (`--dialog-width`, in the `max-w-*` class so `twMerge` still replaces it with an override), `card` with a full `border`, `radius-xl` (12px, `--radius` + 2px) and the shadow `shadow-dialog` (light `0 24px 60px rgba(15, 27, 45, 0.25)`, dark `0 24px 60px rgba(0, 0, 0, 0.5)`, stored as `--dialog-shadow` because a `:root` token named like the `--shadow-*` theme entry would be a cycle). The overlay is `scrim`. The title is the named style `dialog-title` (15/20, 600) aligned left on every width, and the footer has a top `border` across the whole window (a negative margin equal to the window padding, so the 16 consumers that wrap header, fields and footer in one `<Form>` stay untouched). A form field inside `FormField` is 34px (`--field-height`); the height is read from a context variable that defaults to `--control-height`, so the controls in a title row and in table cells stay 32 and 28px, for the reason in ADR-0037 (equal heights in one row). Focus is a 2px `ring` outline everywhere in `ui/*`: buttons and choice elements with a 2px offset, fields with no offset and the border hidden. A button `outline` is `card` + `border` with a `secondary` hover, instead of `background` + `accent`. A disabled button is `muted` + `muted-foreground` instead of `opacity-50` (`ghost` and `link` only `muted-foreground`). "Anuluj" is `outline`, a deviation from `ghost` in `Button/README.md`, as in `context/archive/2026-11-02-approved-plan-changes/plan.md:179`. A choice of one among a few options in a form is `SegmentedControl` `block` in the tone `primary` (equal columns, sent with the form through `name`), a deviation from the `ht-choice` look in `bundle.css`, which is the `neutral` tone. Confirmations, also those with a body (the deficit warning of "Rozpocznij realizację", an `Alert` `warning`), go through `ConfirmActionDialog`, which gets a content slot.

Planning decisions recorded here: the `outline` hover is `secondary` (a global change, as in Atrament); the disabled button look changes in this change, not later; the deficit warning is an `Alert` `warning` because it does not block the save; the unused `DialogScrollContent` is removed; the amount error key is the new `budget.planned_amount_invalid`; the kitchen sink is `/dev/ui/dialogs` with every dialog open in each state. From the research: the dialog shell and the overlay follow Atrament in this change, 34px only for form fields in dialogs, focus 2px globally in `ui/*`, "Anuluj" `outline`, the five hand-written confirmations of the Budget page move to `ConfirmActionDialog`, and a shared `FormField` replaces the copied `Label` + control + `InputError` blocks.

This supersedes in part ADR-0037 (the sentence "the Dialog keeps its radius") and the sentence "Fokus = pierścień 3 px `ring/50`" in `context/foundation/design-system.md`. We rejected a `DialogBody` in the 16 consumers (a rewrite of every dialog for the same look), 34px for every field (a title row and a table cell would differ in height from their neighbours), and `ring-offset` for focus (it needs the colour of the surface, and a button sits on both `card` and `background`; `outline-offset` has a transparent gap).

Superseded in part by ADR-0045: "Anuluj" is `ghost`, not `outline`.
