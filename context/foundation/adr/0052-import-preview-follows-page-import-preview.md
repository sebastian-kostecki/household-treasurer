# Import step 2 follows the design system card PageImportPreview

Step 2 of the Import (`OperationsImportPreview.vue`, with `ImportPreviewRow.vue` and `ImportPreviewSubmitBar.vue`) goes back to the "C · Atrament i morski" design system (artifact https://claude.ai/artifact/9gJSdtfpFgUAa8oEMgR4HA): the card `PageImportPreview` is the reference, as it stands on 2026-11-06. Step 1 already follows `PageImportStart` (ADR-0048). The view kept a title of its own size, a `Card` with `CardTitle`, solid red pills, amounts coloured by the sign in the file and reasons written by the server in English. This ADR records where the view follows the card and where it departs from it, and from earlier ADRs.

Title row. It is built as in step 1 (ADR-0048): `<Head>` and the h1 are "Import operacji" (`import_title`), `meta` says "Krok 2: …", and the exit "Wróć do operacji" is `outline` with `ArrowLeft` and leads to Operations, not back to step 1. The last element of the breadcrumb is "Podgląd importu". The empty state offers "Wybierz inny plik", which leads to step 1. This departs from the h1 of the card: "Pokaż podgląd" is the label of the button in step 1 and the view showed it as the name of the page.

Summary panel. The panel is `ListSurface` with the `#header` slot (`h2.section-title` and `p.meta`), not `.form-panel`, because step 2 is not a form, and not a `Card` with `CardTitle`. The caveat about duplicates stands in `meta`, not in a line of `text-xs` under the panel.

Pills. "Poprawne" and "Poprawny" are `neutral`, "Niepoprawne" and "Niepoprawny" are `destructive-soft`, a duplicate and an own transfer pair are `outline`. `destructive-soft` gets a second meaning: next to an overrun it marks an import row that cannot be imported. The full `destructive` leaves the pills, so a red fill still means only a real error or a delete action.

Amount. The sign and the colour follow the chosen type (ADR-0038): income and refund are `+` with `success`, an expense is `−` with `foreground`. An own transfer and a capital movement go through `formatMoney` with the sign from the file and carry no colour, as `OwnTransferRow` does in Operations. The unit "zł" stands in the cell and the style is `amount`, with no "Kwoty w zł" footer. The import preview is the third exception to ADR-0037, after ADR-0039 and ADR-0044, because these rows become rows of Operations and should read the same before and after the save. The colour of an amount no longer follows the sign in the file, so a row never shows green or red for a type the user has changed.

Reasons. The server sends the rejection code and the data of the candidate (the dates and the account of the pair), not sentences, as the Dashboard sends data and the view composes the text (ADR-0043). The UI builds the sentence from `lang/pl/ui.php` and `formatDate`, so the date reads `dd.mm.rrrr`; a code the UI does not know is shown unchanged and is not dropped. The error of the duplicate acknowledgement is composed in the UI the same way, from `lang/pl/ui.php`; the server's English message stays as the fallback.

Row checkbox. The checkbox of the row is 24 px through the named class `.import-preview-select-check`, because it is the main action of the row and a touch target below 24 px fails WCAG 2.5.8. The confirmation of duplicates is `.form-check-row` (ADR-0048) with its error linked by `aria-describedby`.

We rejected translating on the server with `__('ui.…')` (it would be the first `ui.*` key used in PHP and a second date formatter next to `formatDate`), `lang/pl.json` (the date would stay ISO and the mechanism has no decision behind it), the colour by the sign in the file (the preview would disagree with what is saved), `formatMoneyAmount` with a footer (the preview would disagree with Operations) and removing the 24 px (a target below WCAG 2.5.8 on a phone). It changes no rule in `context/foundation/glossary.md` and no _Avoid_ term.
