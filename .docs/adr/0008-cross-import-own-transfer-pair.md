# Cross-Import pair is one Own Transfer with two Import identities

A later Import row that is the other Account’s view of money already moved becomes that one Own Transfer, not a second record and not a link. If the first file was a Financial Operation, pairing converts it (Execution reverts, then the other Account moves). If it was already an Own Transfer, balances do not move again. We keep two Raw Statement Descriptions and two Import duplicate fingerprints, one per Import-born Account, so re-Import of either file default-deselects; a converted Financial Operation’s identity moves onto the Own Transfer. Live date and description stay the first-leg values. Delete of the Own Transfer drops both identities — there is no separate unpair that restores the Financial Operation. We rejected pairing only against existing Own Transfers (a mistyped first file would never pair), keeping the Financial Operation beside the Own Transfer (Liquidity and Execution would disagree), a second live date, and rewriting live fields from the second file.
