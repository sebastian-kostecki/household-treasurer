# Import category suggestion comes from word weights over the User's earlier Import operations

An Import preview row preselects a Category when the words of its description and Counterparty also appear in the User's earlier Financial Operations that came from an Import (non-empty Raw Statement Description). A word weighs less the more distinct Category name-and-type pairs it appeared under, so card-payment noise (names, city, `POL`, `PLN`) weighs about 0 and a shop name seen under one Category weighs about 1. The suggestion takes the 5 nearest earlier operations (k = 5) and needs a similarity of at least 0.25; below that, on a tie between two names, or with no common heavy word, there is no suggestion. It is computed per type family, Income and Expense (an expense refund uses Expense), when the preview is built, and frozen in the session with the rest of the row. The Category name is mapped to the only active Category with that name and type in the Budget in execution for the year of the row’s date; two matching Categories, an archived one or no such Budget give no suggestion, the same “exactly one match” reading as ADR-0033.

ADR-0010 forbids an Opis preselect or badge on file-one preview; that clause is about the Own Transfer type, and this feature never changes the row type. ADR-0015 and FR-TRX-16 stay intact: the suggestion is computed for the row’s current type and never guesses a refund, so changing the type to refund only reuses the Expense suggestion. ADR-0011 stays intact: the row remains unchecked, because the suggestion changes neither its type nor its selection. FR-IMP-11 stands: bank Category columns are still not mapped; the feature learns from the User’s own classification, and the User can change the value. “AI features” remain out of scope in the PRD: this is deterministic counting, with no model and no external service. ADR-0014 and ADR-0016 stay intact: there is no Category identity across years, the name and type pair is a query, and renaming a Category splits the history.

We rejected Typesense and `pg_trgm` / whole-text similarity (card-payment noise outweighs the shop name), exact text match alone (lower coverage, variant A of the prototype), a suggestion without a threshold, and learning from manual entries (not measured).
